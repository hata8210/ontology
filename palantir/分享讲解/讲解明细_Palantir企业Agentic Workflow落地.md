## 一句话
Palantir 的价值不只在市值，而在它的 Ontology（本体）——它回答企业 AI 最核心的问题：AI 怎样才能理解你的公司、理解你的业务。本期讲清 Ontology 是什么、怎么搭，并落地 Agentic Workflow（智能体工作流）。

## 背景
- 2003 年 PayPal 联合创始人 Peter Thiel 拉上 Alex Karp 创办 Palantir。
- 名字源于《指环王》里的真知晶球。
- 第一笔钱来自美国情报机构 CIA 旗下的风投（当时多数硅谷 VC 拒绝）。
- 产品线：Gotham（情报与军事，最早给情报机构）→ Foundry（商业分析，服务空客、BP、NHS）→ AIP（2023 把大模型带进企业）。
- 2020 直接上市，2024 纳入标普500，2025 营收约40亿美金。

## Ontology 不是什么 / 是什么
- 不是数据仓库、BI 仪表盘、数据目录，也不只是换个名字的语义层。
- 是位于企业数据层与模型层之间的语义层，把分散数据、业务逻辑、操作能力编成一张人类和 AI 都能读得动的可行动的业务地图。
- 例：传统订单表一大堆行；Ontology 让 AI 读懂“客户第3单含5个发动机叶片、目前在德国汉堡待检、关联物流单号、预计到货”这类业务事实。

## 结构
- 用 Object Type（对象类型）取代 DataTable；一行 = 一个 Object，一列 = 属性 Property，对象之间用 Link 相连。
- 三层：Data（数据源）、建模/逻辑层、Action 层（具体操作）。

## 搭建三步（供应链场景）
1. 定义名词：比如供应商 = 供应商ID、区域、交付周期、风险评分。
2. 绑定逻辑：告诉本体怎么计算（库存还能撑几天、补货联系谁）并写成代码、进入本体。
3. 配置执行 Action：谁、能做什么、做什么条件、做完记录，像给“按钮”配权限。

> 人和 Agent 看的是同一张业务地图。

## 从 Ontology 到智能体
- LLM 能聊能写，但不懂业务时只是实习生；本体=给 AI 的企业手册。
- 关键概念是 OAG（基于 Ontology）优于传统 RAG：RAG 只翻文本、易“幻觉”；OAG 直接按结构化业务对象与关系定位、可执行。
- 落地：① 接入 ② 加护栏/安全边界 ③ Agent 推理并执行。
- Human-In-The-Loop：Pal 的说法是“不卖自动驾驶，卖副驾驶（Assistant）”，AI 建议→人审→批准→执行。

## 案例：供应链中断应急
传统：人工 3~5 天在多个系统查、组合、报告。
用 Ontology+AIP：约 15 分钟，五步：
① 后台库存监测，低于阈值触发；2 影响分析（找到受影响订单、估损）；3 生成多种备选方案（估算成本/交货）；4 审批；5 智能执行（下单、回写、通知）。

## 落地 / 注意
- 实际：某药企 <6周 出第一个工作流，后续新增场景只需 90 分钟。
- 成本高、技术偏向 Palantir 生态锁定；多见于大型企业与军工/国家机构。
- 优点：试点周期短、语义建模可复用、全程可审计。

## 三句话记住
1. 护城河不是模型，而是 Ontology；把实体、关系、逻辑、操作建模成 AI 可理解，需要长期行业投入，即 FDE（现场部署与建模工程师）的职责。
2. Ontology = 操作系统，让各 Agent 共享一套语义、权限、规则，建一次、可复用、快速迭代。
3. 语义先行：别跳“先理清业务对象、关系以及操作权限”，否则 Agent 是“盲人摸象”。

## 结语
本体构建前期很重；预告后续会用 LLM 从企业少量数据（FewShot）直接抽取 Ontology。
